# Pad 人脸 / 滑块验证使用方案

> 面向 **iPad（Pad）协议**托管账号。扫码登录时微信可能要求人脸识别或安全验证；
> 这类验证在平台侧完成，**插件本身不需要任何配置**，账号登录成功后插件拿到的
> 网关令牌照常工作。
>
> 操作入口：[云端社交聚合平台](https://cloud.juhe.chat) → 帮助 → **人脸验证**
> （`/support/face-verify`）。这是平台控制台能力，**Hermes 插件侧无需任何改动**。

## 适用场景

- 扫码托管后，控制台提示「需要人脸验证 / 安全验证」。
- 验证页需要在一个能信任平台 CA 的手机浏览器 / 微信内完成。
- 流程只影响**登录**；登录成功后的消息收发、回调、网关调用都不经过验证代理。

## 工作原理

平台在登录链路里挂一个验证代理：验证手机装好平台 CA、把 Wi-Fi 代理指向代理端口后，
微信的验证请求会被代理接管并回传给平台，平台据此完成续接；控制台会持续检测登录状态，
成功后账号变为「在线」。

```
扫码手机：扫码 + 确认登录，停留在等待页
验证手机：安装 CA → 设置 Wi-Fi 代理 → 在微信内打开验证链接 → 完成人脸 / 滑块 / 验证码
控制台  ：检测到登录成功 → 账号在线 → 可签发 wxa_ 网关令牌
```

## 准备条件

| 项目 | 说明 |
| --- | --- |
| 第二台手机 | 推荐。验证过程中切换页面会中断扫码等待流程，单机操作容易失败 |
| 平台 CA 证书 | 控制台「人脸验证」页提供下载（`wechatpadpro-ca.cer`，DER X.509） |
| 代理地址 | 控制台「人脸验证」页显示服务器与端口（默认端口 `18080`） |
| 权限 | 能访问该账号的用户/租户；未开通时页面会提示联系管理员 |

## 步骤 1 · 下载 CA 证书

1. 打开控制台 **帮助 → 人脸验证**。
2. iPhone / iPad 用 **Safari** 打开证书地址；Android / 鸿蒙用 **Chrome 或系统浏览器**打开。
3. 证书文件名 `wechatpadpro-ca.cer`。平台更换证书后才需要重新安装。

> 手机里**不能**填 `127.0.0.1` 作为证书或代理地址——那代表手机自己。

## 步骤 2 · 安装并信任证书

### iPhone / iPad

1. Safari 打开证书地址，出现「已下载描述文件」。
2. 设置 → 通用 → VPN 与设备管理 → 选择该描述文件 → 安装（输入锁屏密码）。
3. 设置 → 通用 → 关于本机 → **证书信任设置** → 为 `WeChatPadPro CA` 打开**完全信任**。

### Android / 鸿蒙

1. 浏览器打开证书地址，保存 `wechatpadpro-ca.cer`。
2. 设置 → 安全 / 安全与隐私 → 更多安全设置 → 加密与凭据 → 安装证书 → **CA 证书**。
3. 选择下载的证书安装；系统要求时先设置锁屏密码。
4. 在「受信任的凭据 → 用户」中确认已出现该证书。

> Android 7 及以上，部分应用（含微信）会拒绝用户级 CA。若仍提示证书不受信任，
> 请改用 iPhone 或能信任该 CA 的验证设备，不建议修改系统安全机制。
> 各家菜单名不同（小米、华为、荣耀、OPPO、vivo、三星、鸿蒙），可在设置里搜索
> 「安装证书」或「代理」。

## 步骤 3 · 设置 Wi-Fi 代理

1. 进入 Wi-Fi 设置，点当前网络右侧的信息 / 设置按钮，把「代理」改为**手动**。
2. 服务器只填控制台给出的主机（不要带 `http://`，不要把端口写进服务器一栏）；
   端口填控制台给出的端口（默认 `18080`）。
3. 「鉴定 / 认证」或用户名密码保持**关闭**，保存并重连 Wi-Fi。
4. **强制停止微信再打开**，否则微信可能继续直连，验证页不会经过代理。
5. 先用手机浏览器打开任意 HTTPS 网站确认网络通，再继续下一步。

## 步骤 4 · 扫码并完成验证

1. 在控制台发起该托管账号的扫码登录，用扫码手机扫码并确认。
2. 控制台出现「需要人脸验证 / 安全验证」后，把验证链接发到**已配置证书和代理的验证手机**，
   在**微信内**打开。
3. 按页面提示完成人脸或滑块；如果控制台出现 6 位验证码输入框，输入手机收到的验证码并提交。
4. 扫码手机的等待页不要退出。控制台检测到登录成功后账号变为在线。
5. 把验证手机的 Wi-Fi 代理改回「关闭 / 无」。证书可以保留，供同一平台下次验证使用。

> 代理开启期间，该手机的部分 HTTPS 流量会经过验证代理。请优先在**备用手机**上临时开启，
> 验证完成后立即关闭，不要在日常主力手机上长期保留代理。

## 插件侧要做什么

| 阶段 | 插件侧动作 |
| --- | --- |
| 扫码 / 人脸验证 | 无。全部在平台控制台与手机上完成 |
| 登录成功 | 在控制台账号详情**签发网关令牌** `wxa_…` |
| 接入插件 | 填 `WPP_CLOUD_GATEWAY_URL` + `WPP_GATEWAY_TOKEN`（或账号 JSON 的 `gatewayToken`）即可 |

登录成功后如果插件仍显示未连接，先排查令牌、网关地址与出站网络，
见 [故障排查](troubleshooting.md)；这不是人脸验证的问题。

## 常见问题

| 现象 | 排查 |
| --- | --- |
| 证书链接打不开 | 手机能否访问平台域名；用 Safari / Chrome 打开；不要用 `127.0.0.1` |
| 设置代理后所有网页打不开 | 代理端口是否放行、代理服务是否在线、服务器地址是否填错（不要带 `http://`） |
| 验证页一直转圈 | CA 未完全信任、仍在用旧证书、端口填错、链接已过期，或没有在微信内打开 |
| 证书装了仍提示不信任 | iPhone 需额外开启「证书信任设置」；Android 必须装成 **CA 证书**，不能装成 VPN / Wi-Fi 证书 |
| 只有一台手机 | 可先完成扫码确认再切换。仍失败时借第二台手机最稳 |
| 验证完成后要不要删证书 | 可保留供下次使用；不再使用该平台或不放心时，在系统证书管理里删除 |
| 换手机 / 换网络后又要验证 | 重新走本流程即可；证书已装过的手机只需确认代理是否打开 |
